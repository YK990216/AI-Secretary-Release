## 1. 認証とID管理 (Authentication & Identity)

### 1.1 ユーザー認証
*   **認証基盤**: [Firebase Authentication](https://firebase.google.com/docs/auth) を利用。
*   **認証プロバイダ**:
    *   **Google**: メインのログイン手段（OAuth 2.0）。
    *   **Microsoft (Azure AD)**: Outlookカレンダー連携用（OAuth 2.0）。アクセストークンはローカルストレージに保存されるが、サーバー側には保存しない。
*   **セッション管理**: Firebase SDKによるトークン管理。
    *   **Short-lived Token**: 1時間ごとにローテーションされるが、SDKがバックグラウンドで自動更新するため、**ユーザーによる再ログイン操作は不要**。
    *   **Long-lived Token**: 別途保持されており、ユーザーが明示的にログアウトするまでセッションは維持される。

### 1.2 ID分離
*   **User ID (UID)**: すべてのデータは Firebase Authentication が発行する `uid` に紐づけて管理する。
*   **データ分離**: Firestore等のデータベースにおいて、常に `/users/{uid}/` をルートパスとし、物理的・論理的に他ユーザーのデータと混在しない構造とする。

### 1.3 バックエンド実行権限 (Cloud Functions / Cloud Run)
*   **公開設定 (Invoker)**: Cloud Runレベルでは「未認証の呼び出しを許可 (Allow unauthenticated invocations)」とする。
    *   *理由*: Firebase Client SDKからの `onCall` リクエストを通すため。
*   **アプリケーション認証 (App-Level Auth)**:
    *   すべてのCloud Functions (`onCall`) 内で、必ず `request.auth` オブジェクトの存在を検証する。
    *   `request.auth` が未定義（未ログイン）の場合、即座に `HttpsError('unauthenticated')` をスローし、処理を実行しない。
    *   これにより、ネットワーク層はオープンだが、アプリケーション層で厳密な認証を強制する**多層防御モデル**を採用している。

## 2. データプライバシーと保存 (Data Privacy & Storage)

### 2.1 ログデータ (Activity Logs)
*   **収集内容**:
    *   ウィンドウタイトル、プロセス名、開始・終了時刻。
*   **キー入力の扱い (Sensing)**:
    *   **仕様**: Pythonセンサー (`focus_sensor.py`) はキーの**打鍵数 (KPM)** とマウスの **移動距離** のみをカウントする。
    *   **禁止事項**: どのキーが押されたか（内容）は**一切記録しない**。キーロガーとしての機能は持たない。
*   **処理場所**:
    *   集中スコアの計算はすべて**ローカルデバイス内**で完結させる。

### 2.2 データベースセキュリティ (Firestore)
*   **アクセス制御 (Security Rules)**:
    *   `request.auth.uid` がドキュメントのパスに含まれる `userId` と一致する場合のみ、読み書きを許可する (Row Level Security)。
    *   他ユーザーのデータへのアクセスはブロックされる。

### 2.3 データ保持期間 (Retention) - *Planned*
*   **ローログ（生データ）**: 30日後に自動削除（またはアーカイブ）。
*   **長期記憶**: AIによって要約された情報（Insight）のみを長期保存する。

## 3. 生成AIと機密情報 (Generative AI Security)

### 3.1 外部API利用方針
*   **APIプロバイダ**: Google Vertex AI (Gemini 2.5 Flash).
*   **認証方式**: **Application Default Credentials (ADC)**
    *   Cloud Functionsに紐付けられたサービスアカウント (`ai-secretary-e7f4e@appspot.gserviceaccount.com`) の権限を利用して認証する。
    *   これにより、APIキーの漏洩リスクを完全に排除する。
*   **Zero Data Retention**:
    *   Google Cloud のエンタープライズ契約に基づき、送信されたプロンプトやデータは、AIモデルの学習には利用されない。

## 4. クレデンシャル管理 (Credentials)

### 4.1 APIキーの廃止 (Deprecated)
*   **Gemini API Key**: v0.4.3以降、生成AIの呼び出しにおいてAPIキーは使用しない（ADCへ移行）。
*   **Firebase Config**: フロントエンド初期化用のConfigは公開情報として扱う（Firebaseの仕様準拠）。セキュリティは API Key の秘密性ではなく、Firebase Security Rules と App Check (将来実装) に依存する。
