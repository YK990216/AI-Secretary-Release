# AI秘書 リリース管理・リポジトリ運用方針

## 1. 概要
本プロジェクトでは、開発資産の保護と一般ユーザーへの製品提供を分離するため、以下の2つのリポジトリを明確に使い分けます。

| リポジトリ種別 | リポジトリ名 (URL) | クラス | 用途・格納物 |
| :--- | :--- | :--- | :--- |
| **開発用** | `YK990216/AI-Secretary` | **Private** | **全資産** (ソースコード全量、全ドキュメント、開発履歴、アイディアメモ等) |
| **公開用** | `YK990216/AI-Secretary-Release` | **Public** | **製品・仕様のみ** (インストーラー、README、製品仕様書、セキュリティ仕様書、マニュアル) |

## 2. 管理方針

### 2.1 開発プロセス (Private側)
*   **普段のコミット**: すべて `YK990216/AI-Secretary` (Private) に対して行います。
*   **ソースコード管理**: 全ての機能追加、バグ修正、リファクタリングはこのリポジトリ内でのみ完結させます。
*   **ドキュメント作成**: 内部設計資料や開発計画も含め、全てのドキュメントはここで管理します。

### 2.2 リリースプロセス (Public側への反映)
製品のバージョンアップ時のみ、以下の手順で公開用リポジトリ (`AI-Secretary-Release`) を更新します。

1.  **成果物のビルド**: Privateリポジトリでインストーラー (`.exe`) をビルドします。
2.  **ファイルの選定とコピー**: 以下の「公開対象リスト」にあるファイルのみを、Publicリポジトリの作業フォルダへコピーします。
3.  **Push**: Publicリポジトリへ変更をPushします。

**⚠️重要**: ソースコード (`src/`, `backend/` 等) は決してPublicリポジトリにコピー・Pushしてはいけません。

## 3. 公開対象ファイルリスト

Publicリポジトリに配置するファイルは以下に限定します。

| ファイル/フォルダ | 元の場所 (Private) | 目的 |
| :--- | :--- | :--- |
| **README.md** | `README.md` (または公開用に調整したもの) | 製品概要の説明 |
| **release/** | `windows-mvp/release/*.exe`, `latest.yml` | インストーラーとアップデート情報 |
| **docs/製品仕様書.md** | `docs/01_製品仕様/AI秘書_製品仕様書_v0.4.3.md` (最新版) | 機能・仕様の公開 |
| **docs/セキュリティ仕様書.md** | `docs/01_製品仕様/AI秘書_セキュリティ仕様書.md` | セキュリティポリシーの明示 |
| **docs/インストール手順書.md** | `docs/04_運用マニュアル/インストール・アンインストール手順.md` | 利用手順の案内 |

---
**運用ルール**:
開発者はこの方針に従い、公開リポジトリへのPushは「リリースタイミング」かつ「指定されたファイルのみ」に限定すること。
必ず作業前に「どのファイルを公開するか」を確認し、承認を得てから実行すること。
