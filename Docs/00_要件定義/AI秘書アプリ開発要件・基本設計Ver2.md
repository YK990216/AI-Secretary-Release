# 次世代AI秘書プラットフォーム開発要件・基本設計仕様書 (Ver 2.2)
**概要**: Antigravityを活用したエグゼクティブ向け自律型エージェント

本仕様書は、GoogleのAntigravityプラットフォームを用いて開発される「次世代AI秘書アプリ」の包括的なガイドラインである。
ドキュメントおよび議事録の「知識化」、多層的なコスト削減策、および心理的摩擦を回避する介入ロジックを統合し、実用性と持続可能性を追求している。

---

## 1. プロジェクトビジョンと開発アプローチ
Antigravityを活用した「エージェント・ファースト」開発を採用する。

*   **Vibe Codingの追求**: 開発者は要件を伝え、エージェントが自律的に実装と統合ブラウザによる検証を行う。
*   **アーティファクトによる透明性**: エージェントが生成する「Task Lists」や「Walkthrough」を通じて開発プロセスの透明性を確保する。

## 2. 秘書業務のAIエージェント化
自動化の適正領域と人間の聖域業務を「実行の正確さ」が求められる領域と、「文脈、感情、政治」が求められる領域に切り分ける。

| 業務カテゴリ | AIエージェントが担う領域 (得意) | 人間が担うべき領域 (聖域) |
| :--- | :--- | :--- |
| **スケジュール管理** | 空き時間の抽出、複数人の予定調整。 | 政治的優先度の判断、断りの調整。 |
| **情報収集・整理** | 議事録作成、メール要約、資料検索。 | 戦略的示唆の提示、リスク検知。 |
| **コミュニケーション** | 定型メールのドラフト、リマインド。 | 相手の感情を読み取った交渉、根回し。 |

## 3. インテリジェントな介入制御と心理的摩擦の回避
経営者の自律性を尊重し、AIが「把握していない状況」を謙虚に認める設計を導入する。

### 3.1. 集中度（Focus Level）の自動検知
PCの操作ログ（KPM/マウス距離）から集中度スコア $S_{focus}$ を算出。閾値を超えている場合や、カレンダーに会議が入っている場合は、通知を自動延期または抑制する。

### 3.2. 謙虚な介入（OAIフレームワーク）
目標から逸脱した際、AIは「命令」ではなく「確認とリスクの提示」を行う。

*   **Ask (確認)**: 「集中を邪魔して申し訳ありません。現在の私の把握していない緊急事項はありますか？ もし状況が変わったのであれば、このまま1時間通知を止めます」
*   **リスク提示**: 「割り込み対応を継続した場合、今日の目標である資料作成の完了率が15%低下する予測です」

## 4. 統合ストレージ戦略とデータ隔離
データの性質に応じた「ハイブリッド・マルチティア・アーキテクチャ」を採用し、セキュリティとコストを両立させる。

| データ種類 | 保存先 | 特徴・役割 |
| :--- | :--- | :--- |
| **意図・設定** | Firestore | SECRETARY.md や今日の目標。低遅延での読み書き。 |
| **操作ログ** | BigQuery | 膨大なイベントデータ。パターン分析と集中度算出。 |
| **書類生データ** | Cloud Storage | 音声、PDF、メール全文。安価なアーカイブ保存。 |
| **AI長期記憶** | BigQuery Vector Search | 要約された事実や合意事項。意味による検索(RAG)。 |

### 4.1. 行レベルセキュリティ（RLS）
BigQueryにおいて、`SESSION_USER()` 関数を用いて、AIエージェントがクエリを実行した際に本人以外のデータが物理的に「見えない」状態を強制し、マルチテナント環境の安全性を担保する。

## 5. ドキュメント・議事録のインテリジェント統合
経営層が持つ「単一の真実（Single Source of Truth）」をAIが常に把握できる仕組みを構築する。

*   **SaaS自動連携 (Google Drive/OneDrive)**: 特定フォルダを監視し、新規ファイルの追加をWebhookで検知。Document AIを用いて複雑なレイアウトや表を構造化して解析する。
*   **議事録自動取得**: 会議終了直後に Meet API 等を通じて文字起こしデータを自動取得。前回の決定事項や未解決の課題を抽出し、事前ブリーフィングに反映させる。
*   **直接アップロード**: チャット画面へのドラッグ&ドロップによる解析もサポート。引用（Citations）機能を備え、回答の根拠となった資料の該当箇所へ即座にアクセス可能にする。

## 6. 技術的なコスト削減策
大量のテキスト処理に伴うAPI課金を抑えるための「多層防御」を実装する。

*   **一次トリアージ (Flash-Lite 活用)**: 最安価な Gemini 2.5 Flash-Lite で情報の重要度を判定。高コストな Pro モデルに渡すデータを全体の10%以下に絞り込む。
*   **セマンティック圧縮 (LLMLingua-2)**: 冗長な表現を削ぎ落とし、トークン数を3分の1から5分の1に凝縮してLLMに入力。
*   **明示的キャッシュ (Explicit Caching)**: SECRETARY.md や頻繁に参照される大型資料をサーバー側にキャッシュし、入力料金を最大90%削減する。
*   **インクリメンタル集約**: 議事録などの長いテキストは、新しい発言の「差分」のみを処理して既存の要約を更新する。

## 7. パーソナル・ステアリング：SECRETARY.md による「教育」
ユーザーが自然言語で「自分専用の絶対ルール」を記述し、AIを即座に調教できる機能を実装する。

*   **記述例**: 「妻からの連絡は集中モードでも表示せよ」「報告は結論から3行以内にまとめよ」
*   **実装**: Firestore内の PersonalPolicy をシステムプロンプトの最上位に注入し、すべての判断スキルのフィルターとして機能させる。

## 8. Antigravityを用いた開発フェーズと指示

### 8.1. フェーズ1：統合ストレージとセキュリティ基盤
*   **指示**: 「Terraformを用いて、GCS、BigQuery RLS、Firestoreを連携させたマルチテナント隔離環境を構築して。90日経過したログをBigQueryの長期保存料金へ移行するポリシーも含めること」

### 8.2. フェーズ2：低コスト解析パイプラインの実装
*   **指示**: 「gemini-2.5-flash-lite を用いたメール・書類のトリアージ・スキルを作成して。スコアが高いものだけをProモデルに渡すルーティングロジックを実装し、コンテキスト・キャッシングを適用して」

### 8.3. フェーズ3：謙虚な介入（OAI）エンジンの統合
*   **指示**: 「PCの集中度とカレンダー予定を監視し、目標逸脱時に『把握していない緊急事項はありますか？』と尋ねる謙虚な通知UIを実装して。ユーザーが拒絶した場合は即座に謝罪し、その文脈を長期記憶に保存すること」

## 9. 結論
本プラットフォームは、Antigravityの自律性とGoogle Cloudの堅牢なインフラを融合させ、経営層に「完璧な記憶」と「質の高い沈黙」を提供する。書類・議事録の徹底したコスト最適化実装は、本サービスの商用的な持続可能性を担保する核心的技術である。
