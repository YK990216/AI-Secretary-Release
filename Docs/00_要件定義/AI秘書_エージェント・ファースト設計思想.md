# 次世代AI秘書プラットフォーム開発要件・基本設計仕様書
## Antigravityを活用したエージェント・ファースト型自律エージェント

本仕様書は、GoogleのAntigravityプラットフォームを基軸に開発される「次世代AI秘書アプリ」の最終ガイドラインである。エージェントが自律的にPC内を探索し、状況をリアルタイムで実況しながらユーザーを支援する「エージェント・ファースト」の設計思想、および**「信頼の境界線（Trust Boundaries）」による厳格な権限管理**の技術仕様を完備している。

---

## 1. プロジェクトビジョンと開発アプローチ

Antigravityを活用した「エージェント・ファースト」開発を採用する。

- **Vibe Codingの追求**
  - 開発者は要件を伝え、エージェントが自律的に実装と検証を行う。
- **アーティファクトによる透明性**
  - エージェントが生成する「Task Lists」や「Walkthrough」を通じて開発プロセスの透明性を確保する。

業務を「実行の正確さ」が求められる領域と、「文脈、感情、政治」が求められる領域に切り分ける。

| 業務カテゴリ | AIエージェントが担う領域 (得意) | 人間が担うべき領域 (聖域) |
| :--- | :--- | :--- |
| **スケジュール管理** | 空き時間の抽出、複数人の予定調整。 | 政治的優先度の判断、断りの調整。 |
| **情報収集・整理** | 議事録作成、メール要約、自律的なファイル探索。 | 戦略的示唆の提示、直感的なリスク検知。 |
| **コミュニケーション** | 定型メールのドラフト、リマインド。 | 相手の感情を読み取った交渉、根回し。 |

## 4. 統合ストレージ戦略とデータ隔離

データの性質に応じた「ハイブリッド・マルチティア・アーキテクチャ」を採用する。

- **Firestore**: 意図・設定などの低遅延データ。
- **BigQuery**: 操作ログの蓄積とパターン分析。
- **Local Disk (SQLite-vec)**: 中期記憶（L1）および書類断片のベクトル索引。

## 5. エージェント・ファースト詳細設計：自律探索と実況ナレーション

エージェントが自律的にPC内を探索し、状況を報告する「エージェント・ファースト」な挙動の内部ロジックを詳述する。

### 5.1. 自律的ファイル探索エンジン (Autonomous File Discovery)

カレンダーの予定から「前回の議事録」や「関連資料」を自律特定するアルゴリズム。

### 5.2. 思考プロセスの実況 (Progress Narration)

エージェントの内部状態（Thoughts）をWebSocket等でストリーミングし、「Analyzed: [Path]」等の形式でユーザーへ報告する。

---

## 6. 信頼の境界線とフォルダ・スコーピング：権限の限定と制御

エージェントが「勝手にシステムファイルを触る」「私的なフォルダを覗く」リスクを物理的に遮断するため、**「サンドボックス化された作業ディレクトリ（Secretary Office）」**の概念を導入する。

### 6.1. 許可ディレクトリ（Allowed Scopes）の明示的指定

- **初期設定（Onboarding）**: 初回起動時に、ユーザーはエージェントにアクセスを許可する「トップレベルフォルダ」を1つ以上指定する。
- **実装**: 指定されたパスを `SECRETARY.md` (Personal Policy) の `ALLOWED_SCOPES` 配列に記録。エージェントはこれ以外のパスに対する読み書き権限を持たない。

### 6.2. ファイルシステム・ツールのバリデーション・レイヤー

エージェントが使用するすべてのファイル操作ツール（read_file, list_directory, write_file等）の入り口に、厳格なバリデーションを挟む。

- **検証ロジック**:
    1.  エージェントが `path` を要求。
    2.  システム（Electron/Node.js側）が `path.resolve()` で絶対パスを算出。
    3.  算出されたパスが `ALLOWED_SCOPES` のいずれかの配下にあるかをチェック。
    4.  範囲外であれば `Access Denied` エラーをAIに返し、理由をログに記録する。
- **技術的ガードレール**: `path.relative` 関数を使用して、結果の文字列に `..` (ディレクトリ遡り) が含まれないことを強制する。

### 6.3. Just-in-Time 権限要求

`ALLOWED_SCOPES` 外のファイルが、カレンダーやメールの文脈から「極めて重要」と判断された場合のみ、AIは一時的なアクセスをユーザーに「打診」する。

- **Askフロー**: 「次の会議に関連する可能性が高いファイルが『デスクトップ』にあります。1回のみ読み取りを許可しますか？」といったポップアップを表示。

## 7. 技術的なコスト削減パイプライン (Model Routing)

- **Stage 1: Triage (Gemini 2.5 Flash-Lite)**: 重要度判定。
- **Stage 2: Prompt Compression (LLMLingua-2)**: コンテキスト圧縮。
- **Stage 3: High-end Reasoning (Gemini 3 Pro)**: Explicit Caching を適用。

---

## 8. セキュリティ・ガバナンス：Human-in-the-loopの強制

外部送信アクション（メール送信、Web検索クエリ等）には必ず Modal Dialog での承認を挟む。

---

## 9. Antigravity を用いた開発フェーズと重要指示

### 9.1. フェーズ1：信頼境界と自律探索の実装

- **Antigravityへの指示**: 「`.agent/rules/secretary.md` に定義された `ALLOWED_SCOPES` 以外のディレクトリ操作をプログラム的に遮断するバリデーション関数 `validatePath` を実装して。すべての file-system スキルの入り口でこの関数を呼び出すこと。また、カレンダー予定から関連資料を探索する際、この許可範囲内のみをスキャンするように `file-crawler` スキルを構成して」

### 9.2. フェーズ2：進捗ナレーションとUI統合

- **Antigravityへの指示**: 「探索の進捗を実況するUIを構築して。権限エラーでアクセスがブロックされた際も『Blocked: [Path] (Scope Outside Allowed Directory)』と誠実に実況ログに残すこと」

---

## 10. 結論

本プラットフォームは、Antigravityの自律性を活かしつつ、物理的な「フォルダ・スコーピング」を導入することで、エグゼクティブに最高レベルのデータ主権を保証する。AIが「触っていい場所」を明確に定義し、それ以外の挙動をシステム的に封じ込める設計こそが、自律型秘書アプリにおける信頼構築の最短距離である。
