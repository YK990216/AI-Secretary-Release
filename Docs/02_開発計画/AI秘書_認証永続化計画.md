# AI秘書 認証・ログイン永続化計画

ユーザーの負担（再ログインの手間）を最小限にしつつ、フェーズに応じたセキュリティレベルを確保するための3段階ロードマップ。

## 🟢 第1段階：個人向け完全永続化 (Seamless Personal Auth)
**コンセプト**: 「自分専用のPCなのだから、一度ログインしたら二度と聞かないでほしい」

- **目的**: PC起動ごとの再ログインを撲滅する。
- **仕組み**:
    1.  **Refresh Tokenの確保**: 初回ログイン時に `offline_access` スコープでリフレッシュトークンを取得。
    2.  **セキュア保存**: Electron標準の `safeStorage` API（Windows DPAPI / Mac Keychain）を使用し、ローカルに暗号化して保存。
    3.  **サイレント・リフレッシュ**:
        - アプリ起動時、Access Token が切れていたら、裏で Refresh Token を使って新トークンを取得。
        - ユーザーには「ロード中...」すら見せず、即座にダッシュボードを表示。
- **再ログインを求められるタイミング**:
    - Google/Microsoft側でパスワードを変更した時（トークン失効）。
    - ユーザーが明示的に「ログアウト」ボタンを押した時。

## 🟡 第2段階：コンテキスト認識型セキュリティ (Context-Aware Auth)
**コンセプト**: 「いつもと違う時だけ、念の為確認する」

- **目的**: 利便性を損なわずに、紛失・盗難時のリスクを低減する。
- **仕組み**:
    1.  **環境指紋 (Environment Fingerprint)**:
        - IPアドレス、Wi-Fi SSID、OSバージョンなどをハッシュ化して記録。
    2.  **異常検知**:
        - 「いつもの自宅」ならパススルー（第1段階と同じ）。
        - 「知らないカフェのWi-Fi」なら、**Windows Hello (生体認証)** や **PINコード** を要求（Googleログインまでは求めない）。
- **再ログインを求められるタイミング**:
    - 全く新しい場所やデバイスで起動した時。
    - 課金や重要ルールの変更など、クリティカルな操作をする直前（Step-up Auth）。

## 🔒 第3段階：エンタープライズ・ゼロトラスト (Enterprise Zero Trust)
**コンセプト**: 「社内規定（コンプライアンス）の絶対遵守」

- **目的**: 企業導入に耐えうる厳格な統制と監査ログ。
- **仕組み**:
    1.  **強制セッションタイムアウト**:
        - 管理者が設定した時間（例：12時間、1週間）で強制的にログアウトさせる。
    2.  **デバイス構成証明 (Device Attestation)**:
        - 会社支給のPC（Intune管理下など）以外からのアクセスをブロック。
    3.  **監査ログ**:
        - 誰が、いつ、どこでログインし、どの情報にアクセスしたかを全て記録・送信。
- **再ログインを求められるタイミング**:
    - 管理者が定めたポリシー期限（毎朝認証など）。
    - 社内ネットワーク外からのアクセス時。
