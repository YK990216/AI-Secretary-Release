# AI秘書 メール解析におけるコスト削減と最適化アーキテクチャ

**作成日**: 2026/02/01
**概要**: 大量メール処理時のAIコスト削減（指数関数的増大の回避）に向けた多層フィルタリング実装案

## 1. 背景と課題
日常的に届く大量のメールをすべて高機能なAI（Gemini 3 Pro等）に読み込ませると、トークン消費量が指数関数的に増大し、運用コストが肥大化する。
これを解決するためには、**「情報の重要度に応じてAIのランクを使い分ける多層フィルタリング」**の実装が不可欠である。

## 2. 実装案 (4つのステップ)
2026年時点の最新技術スタックに基づいた、安価かつ効率的なパイプラインを提案する。

### Step 1: Gmail APIレベルでの「物理的除外」（コストゼロ）
まず、AIに渡す前にGmail APIの検索クエリ（`q`パラメータ）を駆使して、解析不要なメールを排除する。

*   **フィルタリング**: プロモーション、ソーシャル、自動配信の領収書、メルマガなどをクエリレベルで除外（例：`-category:promotions -category:social`）。
*   **メリット**: LLMに送るテキスト量そのものを、API通信前の段階で50〜80%削減可能。

### Step 2: 超低価格モデルによる「一次トリアージ」（コスト98%削減）
すべてのメールをProモデルで読むのではなく、まずは最も安価なモデル（Gemini 2.0/2.5 Flash-Lite）に「重要度判定」のみを行わせる。

*   **実装**: Gemini 2.0 Flash-Lite（100万トークンあたり数円〜十数円レベル）を使用し、メールの件名と冒頭のみをスキャン。
*   **判定ロジック**:
    1.  VIPからの緊急要件
    2.  返信が必要な質問
    3.  ただの共有
    上記3段階に分類し、**「Proモデルで詳細解析が必要なもの」**だけを後続のパイプラインに回す。
*   **効果**: 高単価な推論が必要なメールを全体の10%以下に絞り込み可能。

### Step 3: プロンプト圧縮（LLMLingua-2）の活用
長いスレッドや詳細な本文をAIに送る際、意味を損なわずにトークン数を削減する「プロンプト圧縮技術」を導入する。

*   **技術**: **LLMLingua-2** などの手法を用い、元のテキストから冗長な表現を削ぎ落とし、トークン数を1/3〜1/5に圧縮した状態でAIに入力する。
*   **メリット**: 入力コストを直接的に70%以上削減でき、AIの処理速度（レイテンシ）も向上する。

### Step 4: コンテキスト・キャッシングの徹底
秘書への指示（System Instructions）や、ユーザーが設定したルール（SECRETARY.mdの内容）は、毎回送信するとコストがかさむ。

*   **実装**: Geminiの**Explicit Caching（明示的キャッシュ）**を使用。共通の指示文や長期記憶のインデックスをサーバー側にキャッシュしておく。
*   **効果**: 2回目以降の入力トークン料金を**75〜90%割引**で利用可能。

## 3. コスト削減の構成案（まとめ）

| 処理フェーズ | 使用技術 | コスト感 | 役割 |
| :--- | :--- | :--- | :--- |
| **Stage 1: 収集** | Gmail API (qフィルタ) | 0円 | ゴミメールの物理的排除 |
| **Stage 2: 分類** | Gemini Flash-Lite | 極安 | 「重要」か「無視」かの即時判定 |
| **Stage 3: 圧縮** | LLMLingua-2 | 自社サーバー | 重要なメールの本文を3割に凝縮 |
| **Stage 4: 解析** | Gemini 3 Pro + キャッシュ | 割引適用 | 要約・ドラフト作成・意思決定支援 |
